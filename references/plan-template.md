# 实施规划文档模板

按本模板结构产出规划文档。各节都必填；确实无内容的节写"无"并说明原因，不 silently 省略。落盘路径：`.workbuddy/plans/YYYY-MM-DD-<任务名>.md`。

---

## 各节写作要点

| 节 | 常见错误 | 正确做法 |
|----|----------|----------|
| 背景与目标 | 目标写成动作（"实现登录功能"） | 目标写成状态（"用户可凭账号完成登录并保持会话"） |
| 非目标 | 省略不写 | 至少写一条；最容易被顺带做进去的事放这里 |
| 现状调研 | 复述需求文档 | 写从代码里读到的事实，含文件路径 |
| 验收标准 | "功能正常" | 给可执行命令 / 可点击路径 / 可观测结果 |
| 任务拆解 | 任务粒度过大（"完成后端"） | 每个任务有明确的产出物和完成边界 |
| 实施顺序 | 与依赖列矛盾 | 写完后按顺序走一遍依赖图，确认无环、无前置缺失 |
| 风险 | 只写技术风险 | 已知未知（待用户决策的）也算，这类放确认门里问 |
| 可行性评审 | 三项全写"无问题"，无证据 | 每项给证据；"没验证过"本身就是要点名的条目；结论必须落在本节，不许只在对话里说 |
